# bitbones

A bare bones GUI client for the Bitsocial protocol. Deliberately minimal: no styling opinions, no
product features, every view a thin wrapper over one hook. It exists to make the protocol legible
and to be the fastest place to reproduce a bug against real communities.

## Stack

- Node 22.12.0 (`nvm use`), Yarn 4.17.1 via corepack (`corepack enable`)
- React 19 + Vite 8 (rolldown) + plain `.jsx`, CSS modules
- `@bitsocial/bitsocial-react-hooks` for all protocol access, `@pkcprotocol/pkc-js` in electron only
- zustand 4 for local UI state, react-router-dom 7 with `HashRouter`
- oxlint + oxfmt, knip for dependency hygiene
- electron-forge for desktop, capacitor for android

## Rules

- Run `nvm use && corepack enable` before any command.
- Pin exact dependency versions (`package@x.y.z`), never `^` or `~`. Prefer the exact version 5chan
  already ships when the package is shared — that is the proven-good version in this org.
- Never write "plebbit", "plebones" or "pleb" into this repo. The protocol is Bitsocial, the
  low-level library is PKC (`pkc-js`, `pkcOptions`, `.pkc` data dir), communities are communities,
  never subplebbits. `peers.pleb.bot` and `peers.plebpubsub.xyz` are third-party routing endpoints
  and stay verbatim.
- `useCommunity`, `useCommunityStats`, `useFeed` and `useCommunitiesStates` take a
  `CommunityIdentifier` (`{name}` or `{publicKey}`), never an address string. Go through
  `src/hooks/use-community-identifier.js`. Passing an address silently returns nothing — no throw,
  no console error, just an empty feed or a blank community header.
- `useSubscribe` is the exception: it still takes a plain `communityAddress` string.
- After changing dependencies or the import graph, run `yarn knip`.
- Before pushing: `yarn lint && yarn build`.

## Default community lists

`src/data/vendored-*.json` are generated by `yarn sync:lists` from bitsocialnet/lists. Never hand
edit them. `src/lib/default-lists.js` layers memory -> localStorage (1h TTL) -> vendored mirror and
refreshes in the background; caches are keyed per source so the 5chan/seedit switch cannot serve one
client's list under the other's name.
